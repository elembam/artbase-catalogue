### 3. P973 batches 09/10/11 — filtered upload
**Do not upload all 136 at once.** The rule: upload P973 only for artists whose artist page lists ≥1 catalogued work.

To generate the filtered subset:
```python
import json, glob
from pathlib import Path

artists_dir = Path("artbase_export/data/artists")
artworks_dir = Path("artbase_export/data/artworks")

# Build maker → work count map
makers = {}
for f in artworks_dir.glob("*.json"):
    d = json.load(open(f))
    mid = (d.get("object_id") or {}).get("maker_id")
    if mid:
        makers[mid] = makers.get(mid, 0) + 1

# Artists with QID AND ≥1 catalogued work
for f in artists_dir.glob("*.json"):
    d = json.load(open(f))
    aid = d.get("artbase_id", "")
    qid = (d.get("authority_links") or {}).get("wikidata", {}).get("id")
    if qid and makers.get(aid, 0) >= 1:
        print(aid, qid, makers[aid])
```

Then cross-reference against the QIDs in batches 09/10/11 and upload only the matching lines. Pace — don't stack all three batches back-to-back.

**Why the restraint matters**: The Wikidata community will read the edit history when you propose the artist-ID property in Q3 2026. ## Strategic context

The Latvian art market is small enough that systematic, high-quality presence across Wikidata records for the same named artists becomes conspicuous — researchers and collectors will notice a recurring unfamiliar source and form the question "who is this?" The discovery mechanism only works if:
1. The P973 trail leads to pages worth landing on (now fixed)
2. The landing page has a door to knock on (`catalogue@arsaccordia.com` — now added)
3. Contribution density stays concentrated in Latvian art, where the field is small enough for density to register

The Wikidata property is a lagging indicator — it confirms standing already earned through the give-back, it cannot manufacture it. The right sequence is: keep contributing, grow Mix-n-Match, propose artist ID property in Q3, then passport ID property as the artwork record deepens.
